## Slide 1：业务背景与端侧 OCR 技术痛点分析

### 1. 现状与痛点
* **模型受限**：当前模型所包含的字符集仅有 12 个字符（`0123456789:A`），对于存在其他字母及特殊符号的条码/VIN 码无法进行正确识别。
* **物理畸变严重**：在仓库、车辆港口等真实一线扫码环境中，现场光照多变、扫描角度不固定（如条码颠倒、侧面倾斜拍摄、甚至是旋转 90° 的侧向排布）。
* **端侧硬件性能参差不齐**：不同 PDA 手持机 CPU 能力差异大，且在持续扫码过程中极易因内存抖动和 CPU 发热导致扫描频率急剧下降。

### 2. 本次会议目标
* 梳理打通 **Tesseract (Tessdata)** 和 **PaddleOCR (v4/v5)** 两个平台底座的从零训练与模型微调过程。
* 论证解决 **多角度/偏折文本** 识别问题的工程可行方案。
* 明确 **Android 混合开发（JNI 与 NDK）** 的技术路径，对比选择高性能推理后端（Paddle Lite 或 ncnn）。

## Slide 1.5：深度学习 OCR 核心算法与选型依据

### 1. 为什么用“分割+识别”而不是“单字切分”？
* 传统 OCR 极度依赖单字字符切分。如果字符粘连（如 VIN 码打标紧凑），切分崩溃导致识别全错。
* 深度学习 OCR 通过 **CTC 联结性时间分类**，实现整行图像的免切分预测。

### 2. 文本检测选型：为什么选择 DBNet / DBNet++？
* YOLO 等回归框对倾斜、偏折、透视拉伸的文本行拟合极差。
* DBNet 将文本检测建模为像素级二值化分割，并设计可微阶跃函数支持端到端联合优化。输出多边形顶点，支持 OpenCV 透视变换仿射校正。

### 3. 文本识别选型：为什么选择 SVTR_LCNet？
* 传统 CRNN 中的双向 LSTM（双向循环网络）在移动端 CPU 上**无法并行计算**，高耗时且高内存。
* SVTR 视觉 Transformer 自注意力机制搭配轻量化 LCNet 深度可分离卷积，极大提升端侧计算吞吐。

## Slide 2：技术选型对比：Tessdata vs. PaddleOCR

| 维度 | Tessdata (Tesseract LSTM) | PaddleOCR (PP-OCRv4/v5) (重点建议) |
| :--- | :--- | :--- |
| **检测与识别集成度** | 单一流程，识别严重依赖内置的字符切分逻辑。对于紧凑型字符（如 VIN 码、条码）容易发生多字或漏字。 | **检测 (DBNet) 与识别 (SVTR_LCNet) 解耦**，先做文本行定位切分，再送入识别。对多行、紧凑行适应性极强。 |
| **小样本微调性能** | 所需训练样本量较少，但其网络黑盒化严重，微调易发生过拟合及字符集污染。 | 拥有强大的官方 PP-OCR **大模型底座** 权重，通过 50-100 张样本微调即可在垂直场景取得 95%+ 精度。 |
| **复杂角度与扭曲支持** | 极度脆弱。若文本倾斜超过 15° 或出现 90° 旋转，直接无法识别。 | **支持多边形裁剪 (DBNet++) 与方向分类器 (Cls)**，完美适配旋转、透视倾斜。 |
| **底层可优化空间** | 修改和替换网络结构极其困难。 | 基于 PaddlePaddle/ONNX 开源生态，网络结构清晰，可随意替换 Backbone。 |

## Slide 3：系统流程：从零数据标注到移动端部署

```
【阶段一：数据加工】
  ├── 使用 PPOCRLabel 进行文本框标注与文字标注 (生成 det_list 与 rec_list)
  └── 分析字符分布，自动导出 full_charset.txt 字典文件
        ↓
【阶段二：算法微调】
  ├── Detection: 以预训练 DBNet 为基底，加入旋转、畸变图像增强，训练文本边界拟合
  └── Recognition: 以 SVTR_LCNet 为基底，基于 vincode_full.txt 字典训练字符序列
        ↓
【阶段三：模型打包导出】
  └── 导出推理模型（包含 .pdmodel / .pdiparams 两个核心权重及结构定义）
        ↓
【阶段四：引擎转换】
  ├── 管道 A (Paddle Lite): 运行 paddle_lite_opt ➔ 获得单个轻量 recognize.nb
  └── 管道 B (ncnn): paddle2onnx ➔ onnxsim ➔ onnx2ncnn ➔ ncnnoptimize ➔ 获得 .param 与 .bin
        ↓
【阶段五：端侧部署】
  └── Android 载入模型文件，结合 opencv-mobile 进行图像前处理，多线程预测输出
```

## Slide 4：核心议题一：多角度文本技术方案论证

为了让系统能够兼容 0°、90°、180°、270° 以及各种斜角文本，我们提出四种可行方案进行现场论证：

```
                      多角度文本识别方案选择
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   【方案 A：4分类器】       【方案 B：旋转增强】       【方案 C：仿射变换】
   • 在 DBNet 后面级联        • 在检测和识别训练中        • DBNet 输出多边形
     4-class Cls 模型         加入大量旋转增强           (DBNet++)
   • 分类结果: 0/90/180/270   • 使识别模型对角度免疫     • C++ OpenCV 计算透视
   • 推理端自动逆向旋转       • 缺点: 增大了模型负担       矩阵做 warpPerspective
   • 推荐：精度最高且最鲁棒   • 适用: 小角度倾斜(30°内)  • 适用: 偏折、斜视场景
```

### 方案对比与决议建议：
* **实时扫描（如实时视频流）**：建议选择 **方案 A（4 分类方向分类器）** + **方案 C（透视变换）**。通过 DBNet 检测定位 ➔ Cls 判定角度并校正 ➔ 透视变换拉伸 ➔ SVTR 识别。
* **低性能 PDA（无 GPU 算力）**：建议直接采用 **方案 B**，在训练中加入 $-90^\circ$ 到 $90^\circ$ 随机旋转，免去额外的 Cls 分类模型，减少端侧内存开销。

## Slide 5：核心议题二：端侧推理后端对比（Paddle Lite vs. ncnn）

在将 PaddleOCR 部署至 Android 时，R&D 需在以下两个框架路线中作出选择：

### 路线 A：Paddle Lite (项目当前采用)
* **实现逻辑**：
  $$\text{Paddle Inference} \xrightarrow{\text{paddle\_lite\_opt}} \text{.nb (Naive Buffer) 模型}$$
* **优点**：支持直接加载转换，与百度官方 PaddlePaddle 体系原生兼容，适配平滑。
* **缺点**：对于复杂的网络（如最新的 PP-OCRv5 中的部分注意力层算子）存在兼容性问题，且 Android 运行时体积相对庞大（SO 库文件接近 10MB）。

### 路线 B：ncnn 架构 (nihui 优化管道)
* **实现逻辑**：
  $$\text{Paddle Inference} \xrightarrow{\text{paddle2onnx}} \text{ONNX} \xrightarrow{\text{onnxsim}} \text{ONNX-Sim} \xrightarrow{\text{onnx2ncnn}} \text{ncnn param/bin} \xrightarrow{\text{ncnnoptimize}} \text{Optimized param/bin}$$
* **优点**：
  1. **极致轻量**：SO 运行库极小，内存占用少。
  2. **Vulkan 原生加速**：GPU 算力利用率高，比 Paddle Lite 在中高端芯片上快约 20%~40%。
  3. **模型压缩率高**：通过 `ncnnoptimize` 转成 FP16 混合精度后，模型体积几乎减半，更利于应用包瘦身。
* **缺点**：工具链较长，任何网络结构的微调都需确保 `paddle2onnx` 算子支持。

## Slide 6：工程落地路线图与任务分工

### 1. 数据收集与标定 (下周完成)
* **负责人**：数据组 / 测试组
* **核心任务**：
  * 收集 500 张包含各种偏折角度（0/90/180/270度）、反光、污损的 VIN 码及条码现场照片。
  * 使用 `PPOCRLabel` 或 `LabelImg` 进行统一多边形标注。

### 2. 算法训练与优化 (两周内完成)
* **负责人**：算法研发工程师
* **核心任务**：
  * 基于 PP-OCRv5 结构配置 4 分类器配置文件，运行训练并取得 98% 以上方向分类精度。
  * 将训练数据导出，完成 **ONNX ➔ ncnn** 或者是 **Paddle Lite `.nb`** 的转换。

### 3. 端侧 JNI 集成与编译 (三周内完成)
* **负责人**：Android 开发工程师
* **核心任务**：
  * 引入 `opencv-mobile` SDK 以及 `ncnn-android-vulkan` 构建 JNI 接口。
  * 编写 C++ 层的仿射透视校正（Perspective Transform）与 CTC 解码算法。
